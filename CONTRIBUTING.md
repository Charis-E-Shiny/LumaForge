# Contributing to LumaForge

Thanks for helping. This guide covers setup, standards and how to submit a change.

## Getting Set Up

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements-train.txt
npm install
```

## Making a Change

1. Open an issue first for anything larger than a small fix.
2. Create a branch from `main`, such as `fix/noise-fit` or `feat/tiled-inference`.
3. Keep each pull request to one purpose.
4. Add or update tests.
5. Run the checks below.
6. Open a pull request using the template.

## Checks

These are the same checks that CI runs.

```bash
ruff check lumaforge api scripts tests
pytest -q
npx tsc --noEmit
npm run build
```

## Code Rules

- **Keep the ISP dependency-free.** `lumaforge/isp/`, `lumaforge/hybrid.py`, `lumaforge/degrade.py` and `lumaforge/runtime.py` must not import PyTorch, SciPy, OpenCV or scikit-image, because they run inside the deployed function.
- **Use one implementation.** Training and serving must share the same classical code.
- **Process in the RAW domain.** Sensor degradations belong on the mosaic, before demosaicing.

## Evaluation Rules

These protect the integrity of the results.

- **Keep the test split held out.** Do not use it for training, calibration, threshold selection or model selection.
- **Do not edit numbers by hand.** Reports are generated by `scripts/make_report.py`.
- **Keep the baseline fair.** Improvements to the hybrid must be measured against a calibrated baseline.
- **Change one thing per ablation.** Variants share width, iterations and seed.
- **Report failures.** Regressions belong in the failure analysis.

## Commit Messages

Use a short imperative subject, such as `Fix chroma filter radius at high noise`. Explain why in the body when it is not obvious.

## What Not to Commit

- Dataset files, crop caches or checkpoints
- `.env` files, connection strings or tokens
- User images

## Reporting Bugs

Open an issue using the bug template, and include steps to reproduce. Report security problems as described in [SECURITY.md](SECURITY.md), not in a public issue.
